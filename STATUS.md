# СТАТУС ПРОЕКТА — чекпоинт

## Что это
Десктопный скринер «Plutos для крипты»: детекция торговых роботов и алгоритмов
на **всех USDT-фьючерсах** Binance, MEXC, Bitget, Gate (~3673 символа).

## Запуск
```bash
.venv/bin/python main.py        # окно + бэкенд
.venv/bin/python main.py 2>&1 | tee /tmp/screener_run.log   # с логом
```
Требования: Python 3.9 (системный), venv в `.venv`, зависимости в requirements.txt.

## Архитектура (финальная, вся реализована)
1. **Коннекторы** (core/connectors/) — чанки по лимитам подписок:
   Binance 190/conn, MEXC 150, Bitget 100, Gate 250; стаггер 1.5с; реконнекты
2. **Радар** (core/radar.py) — O(1)-префильтр всех символов: метроном-сниффер
   (7 сделок ±10% интервалов, кулдаун 120с), крупная сделка ≥12×q25, всплеск частоты
3. **Пул** (core/screener.py) — промоушен при score≥80 или 2 метрономах/3мин,
   демоушн через 10 мин тишины, топ-15 каждой биржи постоянно, pool_max 200
4. **Детекторы пула**: таймер-роботы (такт/сила/направление/отпечаток),
   фликер (HFT-частота), спуфинг (исчезающие стены), айсберги (core/detectors/)
5. **История 24ч** (core/history.py): SQLite history.db, батч-запись 1с из очереди,
   retention 24ч, всё под _db_lock; запись открытых символов + авто символов с роботами
6. **Бэктфил** (core/backfill.py): 1-мин klines Binance = мгновенные 24ч (1-2 запроса),
   затем тики aggTrades/futures.trades бюджетно (скип покрытых минут) с fast-forward
   восстановлением флагов роботов; Bitget/MEXC — только своя запись
7. **UI** (ui/): таблица (Инструмент/Биржа/Балл/Радар/Направление/Такт/Принты/Сила/
   Фликер/Спуфинг/Айсберг/Реакция/Длит.), сортировка «свежая детекция наверху»,
   фильтр, счётчики в шапке; индикатор BID ASK: скролл влево, история 24ч с прелоадом,
   зум колесом (время) и Shift+колесом (высота), драг = история, 2×клик = LIVE,
   пиксельная агрегация, автовыбор первого символа через 4с, автозум под 24ч,
   JS-ошибки видны в статус-баре

## Отлаженные проблемы (не возвращаться)
- Bitget ping = сырая строка "ping" (не JSON), лимит подписок 150 упало на 200
- Race UI/asyncio: все вызовы бриджа через run_coroutine_threadsafe (main.py _on_loop)
- SQLite locked: два процесса на один history.db + конкурентные потоки → _db_lock
  + busy_timeout 5000 + insert через очередь writer-потока
- Binance REST 429: бэктфил замедлен до 0.6с/запрос (tick) / 0.3с (klines)
- Gate order_book: уровни могут приходить строкой — _parse_levels с защитой
- Тест-харнесс: не звать Bridge из loop-потока (дедлок) — см. tests/test_bridge_flow.py

## Замеры
3700 символов: CPU ~10% ядра, ~25 WS-соединений; 24ч истории на символ
мгновенно (klines), тики — фон; history.db ~29 МБ на несколько символов

### Что реализовано за сессию
1. **Сканер** (core/scanner.py): топ роста 24ч + счётчик сделок (Binance) + RVOL 1ч≥5;
   RVOL нормализован на долю прошедшего часа; фильтр только вечных фьючерсов (allowed_symbols
   из discovery); вкладки-рейтинги «Топ роста» и «Сделки» (весь рынок, максимум вверху)
2. **Уровни** (core/detectors/levels.py): зонная кластеризация свингов (зона=[min,max],
   слияние пересекающихся, 1 касание = 1 визит >15мин), допуск = 0.5*ATR(14h) с границами
   0.05–0.8%; живой трекинг подходов (номер подхода = touches + инкременты); raw_klines
   хранятся для графика; живое доращивание последней свечи из ленты (_grow_candle)
3. **ММ-детектор** (core/detectors/mm.py): двусторонность, стабильный спред, быстрые
   восстановления уровней, инвентарное смещение, анти-спуфинг (снятие при приближении без
   возврата ≤RESTORE_MS); holding_level() для стратегии
4. **Стратегия** (core/strategy.py): движок «3-й подход» — на 3+ подходе к уровню ★-монеты
   вердикт BREAKOUT/REJECT/UNCERTAIN по факторам: робот по/против движения (RobotSignal),
   ММ держит ли уровень, новости-сентимент; алерты; table_fields(full=...) с дешёвым режимом
5. **Новости** (core/news.py): Binance announcements (bapi endpoint, без ключей), лексикон
   pos/neg, окно 4ч, матчинг по тикеру+алиасам
6. **UI**: вкладки Роботы/Топ роста/Сделки/Сигналы; панель вердикта; колонки Уровни/
   3-й подход/ММ/Новости; **отдельная свечная панель «График»** (ui/chart.js): 1м свечи
   Binance (720), зум колесом, живая цена, уровни = полоса зоны + пунктир средней с числом
   касаний; ценовую линию с BID/ASK убрали (чистый профиль)
7. Мост: get_chart(key, limit) в main.py; get_verdict, get_signals, get_market_table

### Известная проблема (ОТКРЫТА)
**Уровни строятся «неправильно»** по мнению пользователя (даже после зонной кластеризации).
Пользователь завтра пропишет ПРАВИЛА ПОСТРОЕНИЯ УРОВНЕЙ и их ОТОБРАЖЕНИЯ на графике —
переделать core/detectors/levels.py (_cluster_swings, _adaptive_tolerance) и отрисовку
уровней в ui/chart.js по этим правилам. НЕ ПРИДУМЫВАТЬ СВОИ ПРАВИЛА — ждать ТЗ.
